# AI 协作记录（AI_Prompts_Log）

**项目**：K-Means 聚类算法迭代过程可视化
**小组**：拼好组｜**记录人**：袁恒宇（项目经理）
**记录范围**：项目从单文件原型到模块化交付的完整开发过程

## 一、记录说明

本项目把 AI 当作辅助工具使用，主要用于三类工作：**代码结构设计**、**边界情况排查**、**文档与实现的一致性核对**。所有算法细节、界面效果和最终取舍由团队成员确认后才进入代码。

本记录只写真实发生过的事，包含两个部分：

1. **原始指令**：当时实际输入的提示词（可删减，但不改写成书面语）；
2. **AI 的输出与问题**：AI 给的东西哪里能用、哪里错、我们怎么改。

保留 AI 出错的部分，是因为"哪里想错了、人怎么判断"才是使用 AI 的真实过程；只写满分答案的记录没有参考价值。

## 二、开发过程记录

### 记录 1 · 代码结构重构

**背景**：初版是单个 1400 行的 `K-means.py`，界面布局、算法迭代、动画调度、文件导出全部混在一起，同一个文件四个人没法并行修改。

**原始指令**：

> 这个文件一千四百多行，改起来太费劲，帮我按界面、算法、导出拆成几块，算法那块别依赖界面。

**AI 输出**：`kmeans_lab/` 包，划分为 `config / data / initialization / metrics / algorithm / view / ui / animation / export / app / main`，并给出一份"哪个模块可以调用哪个模块"的约定。

**采纳**：

- 包结构与模块边界；
- `view` 只接受 `Scene` 数据快照，不再反向读取控制器（这是能脱离界面测试的前提）；
- `app` 作为唯一胶水层，所有跨模块调用都经过它。

**AI 的问题**：第一版让 SSE 在 `algorithm.py` 和 `metrics.py` 各实现一次，两处会随时间漂移。我们统一为 `metrics.inertia()`，`algorithm` 只调用不实现。

---

### 记录 2 · 数据生成的可复现性

**背景**：需要四种数据形状（三簇高斯、四簇高斯、同心圆、笑脸轮廓），用于展示 K-means 的优势和失效场景。

**原始指令**：

> 帮我生成四种数据：三簇、四簇、同心圆、笑脸。同样的参数要能生成一样的结果。

**AI 输出**：四种形状的生成函数，用 `random.Random(seed)` 控制随机性。

**采纳**：四种形状；坐标统一压缩进 `[0,10]×[0,10]`，保证画布坐标轴固定、切 K 时不会跳动。

**AI 的问题**：第一版直接用全局 `random`，两次调用结果不同，截图无法复现。改为显式传 `rng`，并在测试里加"同参数两批数据必须逐点相等"的断言。

---

### 记录 3 · K-means++ 初始化

**原始指令**：

> 再加一种挑初始中心点的方法，界面上能跟随机选切换，我想对比两种方式。

**AI 输出**：按 D(x)² 概率抽样的实现，返回 k 个样本作为初始质心。

**采纳**：完整保留，与随机初始化并列成可选项。

**AI 的问题**：抽样循环里没有排除已被选中的点，极端情况下会重复选中同一个样本导致质心数不足。补了"已选点距离置 0 + 从剩余点里兜底选"的处理。

---

### 记录 4 · 收敛判定与空簇处理

**背景**：这是算法最容易出错的地方——没有簇分到样本时，质心会变成 NaN，界面直接崩。

**原始指令**：

> 这个迭代过程有哪些容易出错的地方？某一类一个点都没分到怎么办？什么时候算结束？

**AI 输出**：给出"空簇用距离最远的样本点补位""质心位移小于容差即收敛""同时受最大轮数限制"三条建议。

**采纳**：三条全部实现，并在测试里用"12 个完全相同坐标的点、K=3"验证：收敛后 SSE=0，质点坐标全部有限。

**AI 的问题**：AI 最初只判断"簇内样本均值为空就跳过"，那样空簇质心会停留在原位不动，永远不会被再次分配。改成用最远点补位后才真正解决。

---

### 记录 5 · 界面布局与中文显示

**原始指令**：

> 左边放操作区，右边放图。按钮不要被挤出窗口，放不下就滚动。

**AI 输出**：`ttk` + `grid` 布局骨架，四张指标卡、页头、状态栏。

**采纳**：整体结构；左侧栏改为 `Canvas + Scrollbar`，窗口缩小时可以滚动而不是挤压。

**AI 的问题**：AI 给的布局里多处用 `place` 做绝对定位，窗口缩放后控件错位；另外没处理 matplotlib 中文字体，图表标题和坐标轴显示成方块。改为 `grid` + `weight`，并在绘图模块加载前设置 `rcParams["font.sans-serif"]`。

---

### 记录 6 · 置信椭圆的绘制

**原始指令**：

> 每一组点外面画一个椭圆，标出这堆点的范围。

**AI 输出**：用样本协方差矩阵的特征分解求长短轴和旋转角，再按 χ²(2, 0.95)=5.991 缩放。

**采纳**：完整保留；椭圆用虚线绘制，避免和数据点抢视觉重心。

**AI 的问题**：特征值开方前没有做 `max(0, ·)` 保护，当某簇样本几乎共线时出现负值，`sqrt` 直接抛错。补了截断处理。

---

### 记录 7 · 动画节奏与定时器

**原始指令**：

> 点下一步时中心点不要直接跳过去，平滑移过去；连续运行时可以暂停。

**AI 输出**：8 帧、每帧 24ms 的补间动画，用 smoothstep 缓动；连续运行在每轮动画结束后延时再进入下一轮。

**采纳**：帧数与缓动函数保留。

**AI 的问题**：定时器 id 没有保存，关闭窗口时回调还在队列里，控制台报 `invalid command name`。改为记录 `after_id`，在窗口关闭和切换设置时统一 `after_cancel`。

---

### 记录 8 · 单元测试的组织

**原始指令**：

> 帮我写测试，一条命令跑完，告诉我哪项没过。

**AI 输出**：按模块拆分的测试文件，加上一个 `--self-test` 入口，把 `unittest` 的发现和运行包起来。

**采纳**：6 个测试文件共 27 项；`python K-means.py --self-test` 一条命令跑完，退出码可直接用于判断是否通过。

**AI 的问题**：

1. 断言"只有一个簇时轮廓系数为 0"——按定义此时无法计算，应返回 `None`，实现与断言一起改；
2. 测试数据里每个簇都有样本，测不到"空簇"分支，后来补了全重复点的极端用例；
3. 有一个测试直接 import 了 Tkinter 控件，在无图形环境下无法运行，改为只测纯函数。

---

### 记录 9 · 文档与代码的一致性核查

**原始指令**：

> 把 README 和程序实际功能对一遍，不一致的地方列出来。

**AI 核查结果（原 README 确有错误）**：

| 文档原写法 | 代码实际情况 |
|---|---|
| 聚类数 K 支持 2–6 | `MIN_K=2, MAX_K=8`，实为 2–8 |
| 可显示"点到质心的归属连线" | 程序没有该功能 |
| 按钮名为"单步执行""自动播放""生成数据" | 实为"单步迭代""连续运行 / 暂停""生成数据 / 应用设置" |
| 依赖"仅需自带 tkinter，无需 pip 安装" | 必须安装 numpy、matplotlib，否则无法启动 |
| 只列出 5 项功能 | 漏掉手动放置质心、K 值分析、置信椭圆、CSV 与图像导出 |

**采纳**：全部按代码修正，并补了 `requirements.txt`。

**AI 的问题**：核查时曾把"图例放在画布外侧"误判为文档缺失的功能，属于过度推断。所以每条结论都要回代码确认，不能直接采信。

### 记录 10 · 合并冲突的处理

**背景**：`feature/ui` 与 `feature/core` 两条分支都改了侧栏宽度和 README 中同一句功能说明，合并时 Git 报两处冲突。

**原始指令**：

> 这里冲突了，两边都有道理，取哪个？

**AI 输出**：`SIDEBAR_WIDTH` 取中间值 300（312 是为避免侧栏文字换行，288 是为适配 1024 宽屏）；README 保留信息更完整的一版。

**采纳**：按建议解决，并在常量上方补一行注释说明取值依据；删除冲突标记后跑 `--self-test` 确认测试全部通过才提交合并。

**AI 的问题**：没有——但"折中的理由"必须写进代码注释，否则下次还会被改回去，这一点是人工补的。

---

### 记录 11 · 文档配图的自动生成

**原始指令**：

> 文档里的图不想手工截，能不能用代码生成？

**AI 输出**：把 K 值分析弹窗中的绘图部分拆成不依赖 Tk 的 `build_k_analysis_figure()`，再写 `tools/generate_figures.py`，调用项目自身的模块跑出 7 张图。

**采纳**：`view.build_k_analysis_figure()` + 生成脚本，`python tools/generate_figures.py` 一条命令重跑全部配图。

**AI 的问题**：

1. 原先绘图函数和 Tk 窗口写在一起，无法在无窗口环境下导出图片，必须先做函数拆分；
2. 手册放在 `docs/` 下，图片路径若写成 `images/...` 会 404，应为 `../images/...`，这是人工核对时发现的。

## 四、结论与反思

1. **AI 最擅长的是"骨架"**：模块划分、算法公式转代码、测试框架组织，这几块节省了大量时间。
2. **最容易出错的是"边界"**：空簇、重复点、单簇、负数开方——这些恰恰是算法课最看重的地方，AI 默认会走"顺利路径"，必须人工补。
3. **文档一致性只能靠工具化核对**：README 里"写了但没实现"的五处，人工通读三遍都没发现，逐条对照代码一次就全出来了。
4. **凡是 AI 给的折中与判断，理由一定要落到代码注释或文档里**，否则同一个问题会被反复讨论。
